# AIエージェントの行動記録とインシデント対応へのMeDFの適用

**Summary (EN)**: AI agents act through prompts, tool calls, and decisions, but their logs are usually mutable text on the operator's own servers. When an incident occurs, no third party can verify what the agent actually saw, decided, and did. MeDF fixes the *state* of those records — block by block, offline-verifiable, without trusting the operator, a server, or a blockchain. It does not judge whether the agent behaved correctly; it makes the record itself undeniable.

---

## 課題：AIの「行動ログ」は、証拠になっていない

AIエージェントは、入力を受け取り、判断し、ツールを実行し、外部に作用します。しかし、その記録は通常、運用者のサーバー上に置かれたプレーンテキストやJSONのログです。

- 運用者自身が後から書き換えられる（悪意がなくても、整理・削除・再生成で容易に変わる）
- インシデント発生時に、顧客・監査人・規制当局などの第三者が「記録が当時のままか」を検証する手段がない
- ログが大量で、開示したい部分だけを切り出して示すことが難しい

インシデント対応で本当に必要なのは、「AIが正しかったか」の判定ではありません。まず必要なのは、**「何が起きたか」の記録が、改ざんされていない形で固定されていること**です。

## MeDFによる記録モデル

MeDFは、エージェントの実行トレースをブロック単位の文書として固定します。

| ブロック種別 | 内容 |
|---|---|
| `context` | システムプロンプト、ユーザー入力、与えられた指示 |
| `observation` | ツール実行結果、検索結果、外部データの取得内容 |
| `decision` | モデルの判断・計画（思考・出力テキスト） |
| `action` | 実際に実行したツール呼び出しとその引数 |
| `output` | 最終的な応答・成果物 |

各ブロックは RFC 8785 準拠のJSON正規化と SHA-256 ハッシュで固定され、文書全体として検証可能になります。運用者の鍵で署名すれば、「この事業者が、この状態を固定した」という主張も添えられます（署名は信頼の付与ではなく、固定の宣言です）。

検証はオフラインで完結します。検証する側は、運用者のサーバーも、ブロックチェーンも、特定のプラットフォームも信頼する必要がありません。

## インシデント対応の流れ

1. **固定**: インシデント検知時（あるいは定期的に）、実行トレースを MeDF 文書として `pack` し、状態を固定する
2. **保全**: 文書はそのまま保管する。IPFS等に置けば、可用性と内容アドレス性も確保できる
3. **選択的開示**: ブロック単位で参照できるため、関係者には関係部分だけを開示できる（個人情報や機密を含むブロックを伏せた検証も設計可能）
4. **第三者検証**: 顧客・監査人・保険会社・規制当局が、手元の文書だけで改ざんの有無を検証できる
5. **事後分析**: 「どの入力を見て、どの判断をし、何を実行したか」を、改ざんなしに再構成できる

## 規制・ガバナンスとの関係

- EU AI Act は高リスクAIシステムに対して記録（ログ）の保持を求めており、記録の完全性はコンプライアンスの前提になります
- 日本のAI事業者ガイドラインも、透明性と記録・説明可能性を重視しています

MeDFはこれらの要請に対する「記録の固定」という部品を提供します。※ 本書は技術文書であり、法的助言ではありません。

## MeDFがやらないこと（正直な境界）

- **行動の正しさは判定しません**。MeDFが保証するのは「記録が固定時のままであること」だけです。判断が正しかったかの評価は、人間とプロセスの仕事です
- **記録の完全性は保証しません**。「そもそも全部記録されていたか」は、記録する側（キャプチャ層）の設計に依存します。記録漏れを防ぐ仕組み（実行基盤側での自動記録など）は別途必要です
- **時刻の証明は単体では行いません**。法的な証拠性を高めるには、RFC 3161 タイムスタンプ局（TSA）や透明性ログへのアンカーと併用してください

## 統合イメージ

既存のエージェント基盤への組み込みは、薄いアダプタで足ります。

1. フレームワークのトレース出力（プロンプト、ツール呼び出し、結果、最終出力）を上記のブロック種別に変換する
2. セッション終了時または一定間隔で `medf.py pack` を実行し、ハッシュを固定する
3. 必要に応じて運用者鍵で `sign` し、保管・公開する
4. 検証側は `medf.py verify` をオフラインで実行する

```bash
# 実行トレースをMeDF文書化したあと
python3 medf.py pack session-2026-11-03.medf.json
python3 medf.py sign session-2026-11-03.medf.json --key operator.key

# 第三者はオフラインで検証できる
python3 medf.py verify session-2026-11-03.medf.json
```
